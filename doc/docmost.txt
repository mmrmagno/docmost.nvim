*docmost.txt*  Browse and edit supported Docmost pages from Neovim

                                                               *docmost-setup*
Requires Neovim 0.10+, curl and Pandoc. Without Pandoc pages open read-only.
Add the plugin to runtimepath, then: >lua
  require('docmost').setup({ base_url = 'https://docs.example.com' })
<
Production requires HTTPS with normal TLS validation. Uses a normal user session;
no enterprise API key. Internal endpoints vary by Docmost release. The installed
deployment is not yet live-verified. See README.md for NvChad/lazy.nvim setup.

                                                            *docmost-commands*
:Docmost                Open the workspace, or return to where you left it.
:Docmost ui             Same as :Docmost.
:Docmost guide          Editing tips in a small floating window.
:Docmost check          Validate the page text; problems become diagnostics.
:Docmost inspect        Show the block or style under the cursor.
:Docmost cheatsheet     Syntax for every kind of block in a floating window.
:Docmost login          Email input and a local secret password prompt.
:Docmost logout         Forget local session; does not revoke browser sessions.
:Docmost spaces         Select space, page, or children. Load more for pagination.
:Docmost search [query] Search titles/content using the server search endpoint.
:Docmost open {id/url}  Open page as a Markdown acwrite buffer.
:Docmost save           Same save path as :write. Asynchronous; wait for result.
:Docmost reload         Reload only if local edits/outcomes would not be lost.
:Docmost! reload        Explicitly discard local edits after a private backup.
:Docmost diff           Show BASE / LOCAL / REMOTE in a separate diff tab.
:Docmost cancel         Cancel current page operation; writes may still persist.
:Docmost status         Validate session and show current buffer save state.
:Docmost version        Query the optional installed-version endpoint.
:checkhealth docmost    Local diagnostics; does not create or change pages.

Command completion is available. Title is separate from body. The first heading
does not rename a page. Buffers are named docmost://host/page-id. Use :write and
wait before :quit; :wq is not an asynchronous save-and-quit operation.

                                                          *docmost-workspace*
:Docmost opens a floating workspace: a tree of spaces and pages, and a read-only
preview of the selection. It follows your colour scheme and needs no icon font.
The title shows the session: signed in, session expired or signed out.

  j/k, arrows, gg/G    Move between rows.
  Enter                Open page, expand/collapse space, run selected action.
  l / h / -            Expand children / collapse or parent / back to space.
  CTRL-V CTRL-X CTRL-T Open in vertical split / horizontal split / tab.
  /                    Search. Results update as you type.
  p                    Show or hide the preview; on narrow screens, swap to it.
  r                    Refresh or retry the selected row.
  .                    Actions for the selected row (vim.ui.select).
  o                    Open a page by URL or ID.
  a / L                Sign in via a secret prompt / sign out locally.
  w / R / d            Save and verify / safe reload / diff an open page.
  ? / q / Esc          Help / close. Esc in search results returns to the tree.

Children load only when expanded, each level has its own Load more row, and
errors appear under the node that failed. Opening a page closes the workspace
and uses the window you came from; :Docmost restores the same expansion,
selection and scroll. Moving to another editor window also closes it.

Pages you have open are listed first with their save state. w, R and d act on
the selected open page, or on the page you opened the workspace from.

Search: / opens a query line. Typing waits for a short pause, cancels older
requests and ignores late replies. Enter or Down goes to results. Esc returns
to the tree with the previous selection. CTRL-C in the query clears it.

Preview: a separate scratch buffer, never the page buffer. It shows whether the
page is editable (or why not), the open buffer's state and the body. Previews
are cached for the session. ui.preview=false disables remote preview reads.

                                                            *docmost-editing*
Pages are ordinary Markdown buffers. The winbar shows title, editable or
read-only, the save state and a hint. b:docmost_status holds the raw state.
  unsaved            Local edits; :w saves and verifies.
  checking, preparing, saving, verifying
                     A save is running; new edits stay unsaved.
  verified HH:MM     Two fresh reads matched what you wrote.
  conflict           Remote changed, nothing written. :Docmost diff.
  uncertain          Not confirmed. :w checks again by reading; never resends.
  rejected, not saved, blocked
                     Nothing persisted; the hint explains why.
  read-only          No edit permission, Pandoc missing, or a conversion bug.

                                                             *docmost-format*
Docmost stores JSON, not Markdown, so pages use a lossless Markdown dialect:
plain Markdown where possible and Pandoc attribute syntax for the rest. Every
block and attribute has a text form; unknown future blocks use the generic
form. Examples: >
  ---
  title: Release plan
  ---
  [@Marcos]{.mention x-id="u1"}   [text]{.comment commentId="c1"}
  [text]{.underline}   [text]{.highlight color="#ff0"}   $x^2$
  - [ ] task           | a | b | pipe tables
  ::: {.callout type="warning"}
  Body
  :::
  ![caption](src){.image width="600"}   [file.pdf](url){.attachment}
  ::: {textAlign="center"}
  Centered paragraph
  :::
<
A line holding only \ is an empty paragraph; \ at a line end is a hard break.
The title: line renames the page (sent after the body, verified separately).
j: values are encoded JSON; x-id is the Docmost id attribute. Block IDs are
tracked with extmarks, so edits, new blocks and moves keep them in one save.
{...} parts are concealed off the cursor line (ui.conceal). <C-x><C-o> completes
block, style and attribute names. :Docmost check validates without sending.
With LuaSnip, page buffers get snippets: callout, details, columns, task,
highlight, underline, color, math, mathblock, center, newtab, image, embed,
mergedtable. Type the name, accept it, then Tab through the fields.
New images, attachments and mentions still need the browser to create them.
A heading changes the body, not the title. Creating pages is not implemented.
Close the browser editor first, and try a disposable page before real ones.

                                                          *docmost-ui-options*
  ui = {
    width = 0.9, height = 0.86,    fraction of the screen or cells
    border = 'rounded',            none single double rounded solid shadow
    icons = 'unicode',             or 'ascii' for any font
    preview = true,                false: no remote preview reads
    winbar = true,                 page state in page windows
    conceal = true,                hide {...} off the cursor line
    search_debounce_ms = 250,
    preview_debounce_ms = 150,
  }
  edit_title = true                (top level) title/icon header in pages
Two panes from about 107 columns, one pane below, compact on tiny screens.
Highlight groups start with Docmost (DocmostBrand, DocmostSelection, ...) and
link to standard groups. Override them after your colour scheme loads.

                                                                *docmost-auth*
Login cookies are retained in memory by default. Passwords and tokens are sent to
curl via stdin, never argv or shell expansion. TLS is validated; redirects are
refused. Do not paste credentials into chat, command history, or source files.

persist_session=true saves an origin-bound session under stdpath('state')/docmost.
Files are private plaintext (0600); directories are 0700. An external session may
be provided using session_token=function() return vim.env.DOCMOST_SESSION_TOKEN end
or session_file='/private/session.json'. The latter contains base_url and token
fields and must be mode 0600. SSO/MFA browser login flows are not implemented.

                                                             *docmost-safety*
Opening converts the stored JSON to text and checks that it converts back
exactly; blocks that do not are written in a more explicit form, and only if
that also fails does the page open read-only. Saves parse locally, validate,
back up the baseline and edit snapshot, compare two fresh reads against the
baseline, replace JSON on the same page ID, then poll for two stable reads that
match everything sent, including block IDs. HTTP 200 alone never clears
modified. An empty body sends one empty paragraph.

Edits made during a pending save remain modified. Timeouts and ambiguous results
retain an uncertain state; another :write only reads to reconcile, never replays
the update. Use :Docmost diff to inspect differences. Reload cannot discard edits
without explicit :Docmost! reload, and refuses if new edits arrived during reload.

One active editor per page is required. Pre-save checks are NOT atomic. Browser
edits may be unpersisted or arrive during replacement. This is not live Yjs
collaboration. Repeated endpoint reads do not prove storage durability.

                                                            *docmost-backups*
Backups: stdpath('state')/docmost/backups/<instance-page-hash>/*.json
Fields: local_markdown, baseline (JSON, canonical Markdown, metadata), pending.
Retains 20 records per page by default; backup_retention configures this. Backup
failure blocks a save. Remote buffers disable swap and persistent undo files.
Exit/unload backups and same-process recovery preserve normal closing edits;
this is not a continuous journal against process crashes. See README.md to recover
a backup's local_markdown into a scratch buffer after restarting Neovim.

                                                            *docmost-testing*
Run python3 tests/run.py from the repository. It uses local HTTP/HTTPS mocks,
synthetic credentials, and temporary files; it never contacts production. Python
3.9+, Neovim, curl, Pandoc, and OpenSSL CLI are required. Mock success does not establish
deployed server compatibility. Follow README.md's designated-disposable-page
procedure for live verification; configure all real credentials locally.
